# Как читать лог обучения (для ChatGPT)

Проект: человек-ragdoll в Godot учится стоять, потом ходить. Метод: sep-CMA-ES (эволюционный поиск) над весами
маленькой нейросети, которая подправляет заданную позу/походку. Каждое «поколение» проверяется 32 набора весов.

Раз в минуту печатается:

    Идёт 42 мин из 720
    stand: T=2520s stand eps=118 best=7.31 sup=1 sigma=0.142 ok=88 mastered=0
    walk: ещё не начато

- `Идёт N мин из M` - сколько минут обучение шло (суммарно, с учётом перезапусков) и потолок времени.
- Строка на каждую задачу. Задачи идут по очереди: stand (стойка), затем walk (ходьба). Подробная строка только у текущей,
  у остальных «ещё не начато» или «освоено». Это нормально: обучается одна задача за раз.
- `T` - секунд обучения. `eps` - номер поколения.
- `best` - лучшая оценка в последнем поколении (больше = лучше). Для стойки при подвесе 3 около 7.5 - это легко,
  подвес держит тело; важны значения при sup=0.
- `sup` - уровень «подвеса» (страховочной подвязки): 3 сильный, 2, 1 слабый, 0 = без подвеса (настоящая стойка).
  Снижается автоматически, когда 75% лучших кандидатов справляются 3 поколения подряд.
- `sigma` - размер шага поиска. Растёт, пока есть прогресс; если падает до ~0.003, поиск застрял.
- `ok` - процент из 8 лучших кандидатов, которые справились: не упали, корпус вертикален (>0.8), высота >80% нормальной,
  а для ходьбы ещё прошли больше 1 м.
- `mastered` - сколько поколений подряд текущая средняя модель стоит при sup=0. Нужно 10, тогда задача освоена.

Служебные строки: `>>> Подвес снижен до N` и `>>> Задача «...» освоена без подвеса. Идём дальше.`

Признаки проблем: sup не снижается долго при ok < 75; sigma у минимума; best не растёт часами; ходьба с большим best
при маленьком пройденном расстоянии (возможна «хитрость» с подвесом).
